# Polkit real — validação de 28/10/2026 / Real Polkit validation

## Português Brasil

**Aprovado: 11 cenários GUI e uma recusa sem sessão local.** O ensaio foi repetido
com a preparação limpa documentada, a partir de uma imagem Ubuntu Minimal oficial
verificada por assinatura e SHA-256. O host executou QEMU como usuário comum e
conectou apenas dois arquivos novos: raiz de 3 GiB e USB virtual de 64 MiB.
Nenhum disco físico ou senha do usuário foi utilizado.

O fixture compila o código real da GUI e executa `begin_write`, `LufusJob`, leitura
de eventos, espera e cancelamento. A escolha/confirmação inicial é preparada pelo
fixture. `pkexec`, Polkit 124 e PAM são reais; o helper elevado é o executável
inalterado do pacote 0.3.6. Um agente automatizado responde com uma credencial
aleatória de uma conta administradora criada somente no guest. Não foi criada
regra que dispense autenticação. Autorizações temporárias são revogadas entre
casos para não mascarar uma nova solicitação.

| Cenário | Layout instalado | Layout portátil | Resultado conferido |
| --- | --- | --- | --- |
| Senha correta e escrita RAW com verificação | Aprovado | Aprovado | PAM autorizou; GUI concluiu; bytes gravados foram comparados independentemente |
| Agente recusa a solicitação | Aprovado | Aprovado | Sem confirmação de sucesso e sem mudança no SHA-256 do dispositivo completo |
| Senha incorreta | Aprovado | Aprovado | Sem autenticação e sem alteração no dispositivo |
| Cancelar enquanto autentica | Aprovado | Aprovado | GUI cancelada, nenhuma confirmação de conclusão e dispositivo intacto, inclusive quando a autenticação termina depois do pedido |
| Cancelar durante escrita | Aprovado | Aprovado | Helper root interrompido e GUI cancelada; mídia parcialmente alterada não foi apresentada como concluída |
| Sessão local tornada inativa por troca de VT | Aprovado | Fora deste caso | A política do aplicativo recusou sem desafio de senha e sem escrita |
| Chamador sem sessão local | Aprovado, chamada separada | Fora deste caso | `pkexec` recusou a execução pela política do aplicativo |

O layout instalado usa um wrapper root em `/usr/libexec/tuxflash-helper` e a
política original do projeto. O layout portátil resolve o helper no runtime e
usa a ação genérica de execução do Polkit. Portanto, a recusa de sessão inativa
pela política específica não deve ser generalizada ao caminho portátil.

Ambiente: Ubuntu Minimal 24.04 (origem datada 20261027), kernel fornecido
7.0.0-38-generic, QEMU/TCG, duas CPUs virtuais, 1408 MiB, Xvfb e GTK do runtime
privado. Pacotes: Polkit/pkexec `124-2ubuntu1.24.04.4`, systemd/libpam-systemd
`255.4-1ubuntu8.18`, Xvfb `2:21.1.12-1ubuntu1.9`. A rede foi usada na instalação
dos pacotes; os links foram desativados antes da bateria. Secure Boot desativado.

Helper SHA-256: `d0482e84a284898fc04cc11d5d0955a3019df4e5c19c95184893cc8775959d50`.
A origem oficial, hashes de kernel/fixture/política e resultados estão no
[resumo sanitizado](evidence/linux/tuxflash/road-to-1.0/polkit-real/results.json) e
[registro de casos](evidence/linux/tuxflash/road-to-1.0/polkit-real/cases.log).
O código do fixture compilado corresponde ao commit `c2a6e39`; os guardas de
entrada do harness foram reforçados depois e testados separadamente para recusar
o host, inclusive com Python otimizado. Isso não muda os cenários de autenticação.

### Alcance e pendências

Esta é validação posterior da 0.3.6, sem alterar o binário público. A bateria
não substitui agente visual GNOME/KDE, instalação Debian/RPM, retirada física,
encerramento abrupto da GUI, outros kernels/distribuições, Windows completo,
persistência ou Windows To Go até o desktop. Cancelar a escrita não restaura
os dados anteriores do destino. Os critérios ainda abertos estão no
[roteiro para a 1.0](../development/ROADMAP-1.0.md).

O [procedimento reproduzível](../development/POLKIT-VM.md) inclui isolamento,
verificação de origem, guardas do host e interpretação dos resultados. Imagens
com credenciais de teste e logs brutos permanecem privados; só os resultados
sanitizados entram no repositório.

## English

**Passed: 11 GUI cases plus one sessionless rejection.** The clean preparation
used a signature/SHA-256-verified official Ubuntu Minimal archive. An ordinary
host user ran QEMU with only two new regular image files; no physical disk or
personal credential was used.

Actual GUI job-start/read/wait/cancel callbacks, `LufusJob`, real `pkexec`,
Polkit/PAM and the unchanged 0.3.6 root helper were exercised. Initial target
selection/confirmation is fixture-provided. An automated official-API agent
uses a random guest-only admin credential; no rule bypasses authentication.
Temporary grants are revoked between cases.

Installed and portable paths each passed approved write/read-back, agent
dismissal, incorrect password, cancellation during authentication and during
writing. Refusals and pre-write cancellation left the full-device SHA-256
unchanged. Mid-write cancellation returned a cancelled UI state without a false
completion; it does not roll back target data. The installed path additionally
rejected an inactive local session without a password challenge and rejected a
separate sessionless caller. Portable execution uses Polkit's generic action;
installed-policy inactive-session behavior is not claimed for that path.

The supplied 7.0.0-38 kernel, Ubuntu 24.04 userspace, Polkit 124, systemd 255,
1408 MiB/two-vCPU TCG VM, Xvfb and private GTK runtime are recorded above.
Guest package installation used networking, then links were disabled. This is
not a stock-kernel distro matrix, GNOME/KDE human-agent test, Debian/RPM install,
physical disconnect, abrupt frontend exit or full OS/persistence qualification.

The linked JSON/log provide sanitized results and fingerprints. The fixture
compiled for the VM came from commit `c2a6e39`; later host-entry guards were
separately tested, including optimized Python, with authentication scenarios
unchanged. The public application remains 0.3.6. See the linked reproduction
guide and 1.0 roadmap for procedure and remaining work.
